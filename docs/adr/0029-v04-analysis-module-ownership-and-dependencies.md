# V0.4 bündelt Analysen hinter einer tiefen Analysis-Seam

V0.4 ersetzt `resting_hr_analysis` durch ein tiefes `analysis`-Modul, das alle vier eingebauten Analysedefinitionen, Analyseeingangsbündel, Lauflebenszyklen, Ergebnisfamilien und die Persistenzkoordination besitzt; die drei Modellfamilien bleiben private Implementierung. `storage` behält Identitäten, Writer-Lock, Staging, Integritätsprüfung und atomare Veröffentlichung über einen analysespezifischen Publikationsauftrag, während `application` das bisherige `overview`-Modul aufnimmt und Auswahl, Kohärenz und die fokussierten präsentationsneutralen Projektionen besitzt. Der V0.3-Abhängigkeitsgraph bleibt bis auf `application -> analysis -> storage` und die beiden ersetzten Module unverändert; generische Analyse-Engines, Registries, Repositories, Projektions-, UI-, Feature-, Statistik- und Vertragsmodule bleiben ausgeschlossen.
